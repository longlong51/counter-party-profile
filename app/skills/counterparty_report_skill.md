# 交易对手方画像报告生成 Skill

> 本文件是 Agent3（报告生成）与 Agent4（校验）共同遵循的流程规范，运行时由 `counterparty_graph.py` 读取并注入提示词。

## 1. 适用场景

对任一交易对手方（银行、券商、基金公司、保险、非金融企业）生成一页式画像报告，用于：
- 交易前对手方准入与额度评估；
- 回购/衍生品交易的对手方风险复核；
- 定期复评（季度/半年）。

## 2. 输入

| 输入 | 来源 | 是否必需 |
|---|---|---|
| 对手方名称 | 用户请求 | 必需 |
| 主体信息（统一社会信用代码、注册资本、法人、成立日期） | MCP `enterprise` | 建议 |
| 评级（主体/债项/展望/评级机构） | MCP `bond` / 公告解析 | 建议 |
| 财务指标（总资产、负债、营收、净利、资产负债率、ROE） | MCP `bond_financial_data` / 财报 PDF | 建议 |
| 风险事件（被执行、失信、破产重整、行政处罚、经营异常） | MCP `enterprise` | 建议 |
| 交易行为（存续债、存单发行、成交） | MCP `bond` / 交易所公告 | 可选 |
| 知识库条款（E 类尽调、F 类信用风险、B 类清算交收） | RAG 检索 | 必需（用于校验） |
| 用户上传文档解析结果 | Redis 缓存 | 可选 |

## 3. 报告结构（固定七段）

1. **结论摘要**（3–5 条）：合作建议（可准入 / 有条件准入 / 不建议）、主要理由、主要风险点。
2. **主体信息**：名称、统一社会信用代码、机构类型、注册资本、成立日期、法定代表人、上市标志。
3. **评级情况**：评级机构、主体评级、展望、债项评级、评级变动。
4. **财务概况**：报告期、总资产、总负债、营业收入、净利润、资产负债率、ROE。
5. **交易与清算要点**：该对手方所属交易场景适用的结算安排（DVP/CCP/分级结算）、对手方违约时的处置路径（引用知识库 B/C 类条款）。
6. **风险与合规事件**：事件类型、日期、金额、描述、来源。
7. **尽调与后续动作建议**：需补充的材料（受益所有人、实际控制人、关联方），复核频率（参照 E 类条款：最高风险客户每年至少审核 1 次）。

## 4. 五维评分规则（0–100，规则法计算，避免模型臆断）

| 维度 | 计算口径 |
|---|---|
| 主体实力 | 上市 +20；注册资本可识别 +20；成立满 10 年 +20；机构类型为持牌金融机构 +40 |
| 财务稳健 | 资产负债率 ≤60% 记 90；60–80% 记 70；>80% 记 50；数据缺失记 60（并标注缺失） |
| 信用资质 | AAA=95，AA+=85，AA=75，AA-=65，A 及以下=50；无评级记 55 |
| 交易活跃 | 存续债券/存单 ≥3 只 90；1–2 只 75；0 只 60 |
| 合规风险 | 无风险事件 90；1–2 条 75；3–4 条 60；≥5 条 40 |

综合建议：五维均值 ≥80 → 可准入；60–79 → 有条件准入（限额+增信）；<60 → 不建议或需人工尽调。

## 5. 写作规则

- 所有金额、比例、日期必须来自输入数据，**不得推算或补全**；缺失写「未获取」，不得留空或写 0。
- 每个结论句后标注依据：`[数据: MCP]`、`[数据: 上传文档]` 或 `[规则: 知识库标题]`。
- 不输出投资建议、不预测股价/评级调整。
- 涉及监管口径时，优先引用现行有效且生效日期最新的条款；引用征求意见稿须注明「征求意见稿」。
- 示例数据（`data_source=mock`）时，报告首行必须标注「示例数据，待接入真实数据源」。

## 6. 校验清单（Agent4 使用）

| 编号 | 检查项 | 不通过时的修正建议 |
|---|---|---|
| C1 | 报告主体名称与请求一致 | 统一为请求主体名，删除其他主体内容 |
| C2 | 评级同时给出主体与债项，且注明评级机构 | 补全缺失项或标注「未获取」 |
| C3 | 财务表至少含资产负债率与 ROE，且标注报告期 | 补报告期或标注缺失 |
| C4 | 风险事件每条有类型、日期、来源 | 补齐字段，无来源的删除 |
| C5 | 「交易与清算要点」引用知识库条款且条款现行有效 | 替换为现行有效条款或删除 |
| C6 | 结论与五维评分方向一致（无「评分低但建议准入」矛盾） | 调整结论或说明例外理由 |
| C7 | 无编造数字（与输入数据可逐项核对） | 删除无法核对的数据并标注「未获取」 |
| C8 | 示例数据场景已标注 | 首行补「示例数据」提示 |

校验输出格式：

```json
{"issues": [{"level": "high|medium|low", "field": "评级", "problem": "缺债项评级", "fix": "补全或标注未获取"}], "passed": false}
```

## 7. 失败与降级

- MCP 不可用：使用 `data/reference_reports` 中已解析的公开报告 + 缓存，报告标注 `data_source=local_fallback`。
- LLM 不可用：使用模板化报告（结论摘要由规则生成），标注 `template_mode=true`。
- 校验两轮仍不通过：报告照常输出，但 `status=needs_review`，并在 PDF 中加入「自动校验意见」章节。
