# 版本检测与更新

当用户希望检查更新，或现有技能可能版本滞后时，按以下流程处理。

## 1. 检查版本信息

读取当前技能目录中 `SKILL.md` 的 `metadata.version` 字段，并查阅最新的[官方安装指南](https://mcp.51ifind.com/gwstatic/static/ds_web/ifind-mcp-web/skills/SKILL_INSTALL_GUIDE.md)，获取当前发布信息及安装包地址。

> 注意: 该指南面向首次安装，更新时仅按需复用下载、解压、环境检查及自检流程。不要直接执行其中的自动安装或删除当前安装目录步骤。

版本信息以执行时的官方发布信息及安装包内 `SKILL.md` 为准，不写死版本号，也不根据下载链接或文件名推断实际版本。若指南未提供可确认的版本信息，应告知用户“线上版本尚待核实”，询问是否允许下载到临时目录并解压核验；未经同意，不下载或解压安装包。

向用户说明本地版本、线上版本及其依据。无法获取或确认时，如实说明原因；确认无需更新时，告知用户并结束检查。若线上版本低于本地版本，不自动降级。

## 2. 确认更新与现有内容处理方式

发现可用更新后，先告知用户版本差异，询问是否下载安装。

安装前检查当前技能目录中的配置、自定义脚本、文档改动及其他个性化内容，向用户说明检查结果，并确认安装位置及现有内容的处理方式，例如备份后替换、保留并迁移指定内容，或安装到其他目录。无法判断文件是否经过修改时，应明确说明，不能默认其可被覆盖。

保留 `config/mcp_config.json` 中的有效密钥与 `config/skill_env_config.json` 中的环境配置，不展示完整密钥，也不以安装包中的默认配置覆盖。其他个性化内容按用户确认的方案处理。

**下载、解压、备份、安装、覆盖、迁移或删除文件，均须在用户同意的范围内执行。仅同意检查版本，不代表同意下载或安装；仅同意下载核验，不代表同意覆盖当前安装目录。**

## 3. 执行更新并验证

取得相应授权后，使用最新官方指南提供的安装包地址，在独立临时目录下载、解压，并核对包内版本。若实际版本与此前信息不符，先告知用户并重新确认后续操作。

按已确认的方案处理现有内容，再安装并检查运行环境。复用指南中的 `listTools("stock")` 或 `list_tools("stock")` 方法完成自检；不要将直接运行 `scripts/call-node.js` 或 `scripts/call.py` 视为自检通过。缺少有效密钥时，先引导用户完成配置，不使用占位符发起请求。

完成后报告实际安装版本、安装目录、现有内容处理情况及自检结果，并在授权范围内清理临时文件。更新或自检失败时说明原因和当前状态，不自动删除现有安装或继续覆盖；必要时提示用户重新加载技能或重启智能体。
